Get started

Work outlives the terminal.

Install and run Read the source

Ceraa runs your coding agent as a durable service with a Telegram bridge. Sessions, model steps, tool operations and recovery checkpoints are written as JSON, so closing the laptop does not end the run.

ceraa service running 
$ ceraa setup      # asks only for the Telegram bot token
$ ceraa doctor    # config, provider, Telegram, workspace, storage
$ ceraa start     # durable service, foreground
$ ./bin/ceraa ask "list files in ."

# terminal closed. session, steps and tool
# results stay on disk. resume from Telegram
# or from ./bin/ceraa chat, same engine.
✔ step 7/12 durable

Engine

One engine, two surfaces.

The CLI and the Telegram bridge are not two products sharing a protocol. They call the same runner, so a session started in a terminal can be continued from a phone and finished back at the shell.

Shared agent engine

CLI and Telegram both run harness/coordinator.Runner. One implementation, one set of semantics, no drift between surfaces.

Native tool definitions

The model sees one terse contract per registered tool. Usage guidance lives in the system prompt instead of the descriptions, so the schema stays small.

Concurrent tools

Tool calls from a single model response run concurrently, with cancellation, permissions and durable result records for each one.

Telegram bridge

Long polling, a strict user and chat allowlist, inline keyboards, callback controls, a persistent Menu button, and a Mini App served on loopback.

Durability

What survives a disconnect.

Durability is the product. Everything below is persisted, not held in memory and lost when the process ends.

  • sessions Persisted as JSON.A session is a file, not a live socket. It can be reopened later by any surface.
  • model steps Every step recorded.Each model turn is written, so a resumed run knows exactly where it stopped.
  • tool operations Results are durable too.Concurrent tool calls keep durable result records, so completed work is never repeated on resume.
  • checkpoints Recovery points.Checkpoints mark recoverable boundaries across a crash, a restart or a moved machine.
  • scheduled jobs Durable scheduling.Scheduled jobs persist alongside sessions rather than living in a cron entry.

Behaviour

Built to be checked, not trusted.

Adaptive workflows

Compact project memory, approval-based skill proposals and evaluation baselines. Nothing is adopted without you approving it.

Cost visibility

Usage is tracked by input, output, cached input, cache writes, reasoning and total tokens. OpenRouter pricing is refreshed daily, and stale prices are never used silently.

Doctor

ceraa doctor checks configuration, provider reachability, Telegram connectivity, workspace access and writable storage before you rely on any of it.

Single daemon

A second start is refused, not queued. The daemon records its pid, process group and start time before its first poll, so two daemons cannot fight over one Telegram offset.

Commands

The whole surface.

commandwhat it does
ceraa setupAsks only for the Telegram bot token.
ceraa doctorChecks configuration, provider reachability, Telegram connectivity, workspace access and writable storage.
ceraa startRuns the Telegram service in the foreground. Refuses if one is already running.
ceraa stopStops a running service with an 8s grace, then clears a stale pid file.
ceraa restartRestarts in place. The daemon execs a new image of itself, so its pid and environment are preserved.
ceraa versionPrints the version and the licence notice.
ceraa chatOpens an interactive terminal session.
ceraa askRuns a single instruction, for example ceraa ask "list files in .".
There is no default provider. Ceraa ships with no provider URL, model or key and picks none on your behalf. On first run it asks which provider to use and stores that per provider. CERAA_API_URL, CERAA_MODEL and CERAA_API_KEY can pre-seed one from the environment instead.
